# Agent Kanban 产品设计

由 2026 年 10 月 6 日的[分享讨论](https://chatgpt.com/s/cx_6ac5003636788191bb9c7a03ce113173)整理，并结合本轮用户补充：执行器候选暂定为 Codex、Claude、Cursor 三种。

- `prd.html`：产品需求文档，含需求编号、工作流、权限、数据模型、验收标准与待定决策。可使用页面按钮打印或保存 PDF。
- `design.html`：软件设计文档，包含原生架构、领域模型、调度与停止、执行器适配、权限、导入、恢复、内部契约及 18 项需求验收映射；支持全文搜索、浅深色和打印。
- `design-content.js`：设计文档结构化内容源；正文已静态内嵌至 `design.html`，阅读无需单独加载。
- `prototype.html`：macOS SwiftUI 方向的 HTML 交互原型。所有任务、模型输出、审批和代码变更均为演示数据。
- `prd-content.js`：PRD 的结构化内容源，已内嵌至 `prd.html`，阅读时不需要单独加载。
- `task-import-helpers.js`：CSV/TSV 解析与导入演示数据工具，已内嵌原型，无外部依赖。
- `model-selection-helpers.js`：执行器对应模型、推理强度能力与配置快照的演示工具，已内嵌原型。
- `execution-permission-helpers.js`：执行器原生权限/隔离选项、按执行器恢复与运行快照的演示工具，已内嵌原型；不执行真实沙箱。
- `VALIDATION.md`：实际检查结果与验证边界。
- `screenshots/`：看板、任务详情、项目导入、项目会话以及 PRD 预览图。

直接在浏览器打开 HTML 文件，或在此目录启动本地 HTTP 服务。PRD、软件设计与交互原型均不依赖外部字体、脚本或服务。原型使用浏览器本地存储保存演示状态，不提供“重置演示”或已移除项目恢复入口。

HTML 是需求评审载体，最终产品最低支持 macOS 26.0，使用 SwiftUI 系统 Liquid Glass 与原生控件，不增加 macOS 25 及以下兼容方案。执行器范围暂定为 Codex、Claude、Cursor，不表示三种均已接通或兼容；首个实现、接入方式与顺序仍待定。Codex app-server 和 Claude Agent SDK 桥接仅为建议接入方案、待实测；Cursor 已补充官方接入调研，建议优先验证本地 CLI ACP，SDK Bridge 为备选，Headless CLI 用于批处理，Cloud API 留待扩展。本机已完成 ACP 初始化握手、CLI 认证状态/模型目录读取及当前 ACP 源码核对；真实会话切换、模型推理、审批、取消与权限仍待联调。后续 Adapter 也限定在这三种范围内。

材质遵循 Apple 的 [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass) 与 [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：玻璃用于导航、工具栏、输入控件与菜单浮层，正文、任务卡及代码 diff 保持稳定易读的内容底色。设计适配浅/深色及“减少透明度”“减少动态效果”“增加对比度”；HTML/Figma 仅模拟材质，SwiftUI 系统效果和无障碍实测须在原生实现中验证。

普通项目会话和任务主会话参考 Codex 布局：输入框底部以单一紧凑入口展示执行器、模型与随档位变色的强度摘要，点击先显示紧凑强度面板，再点击中部模型名称进入执行器/模型列表，支持键盘和窄屏；各自独立保存；Cursor 是执行器候选，不是模型名称。建议任务可继承项目默认执行器，模型与支持的强度由各会话/任务分别选择。每次回复/Run 冻结执行器、模型 ID/显示名和强度快照，运行中修改只影响下一次；切换执行器保留逻辑 Conversation 和历史，协议无法复用时关联新的 executorSession。实际模型目录与强度来自 Adapter/账户能力，无能力或未知时显示执行器默认/未开放，不发送伪参数；兼容性变化导致回退需明确说明。界面不设独立设置页，不提供项目默认模型、可配置并发上限、单次运行预算和全局代码分析开关。单任务唯一活跃主运行、同目录唯一写入者、按需只读分析和失败恢复规则继续保留。

模型目录改为 2026-10-07 核对的精确版本快照。正式产品从各执行器/账户获取并刷新目录缓存，显示完整版本，保存实际 API ID、能力来源和检查时间；不能把 latest 别名当版本，Auto 路由模式不编造版本号。HTML 保持离线目录与模拟回复，不自动实时同步，也不改写历史 Run 名称。

Codex 目录来自 CLI 0.160.1 的本机公开新鲜缓存，快照时间 `2026-10-07T03:49:48.735814Z`。可见模型为 GPT-6.1-Sol、GPT-6-Astra、GPT-6-Sol、GPT-6-Luna、GPT-5.6-Sol、GPT-5.6-Terra、GPT-5.6-Luna；两个 Luna 支持 low/medium/high/xhigh/max，其余还支持 ultra。6.1-Sol、5.6-Sol 默认 low，其余默认 medium；hidden 不显示。见 `research/codex-model-catalog.json`；本轮实时 model/list 初始化被只读探针阻断，缓存读取不等同模型推理授权。

Claude 当前为 Fable 5.1（`claude-fable-5-1`）、Opus 5.5（`claude-opus-5-5`）、Sonnet 5.5（`claude-sonnet-5-5`）与 Haiku 4.5（`claude-haiku-4-5-20251001`）；前三支持 low/medium/high/xhigh/max，Haiku 不提供独立 effort。依据[官方模型目录](https://platform.claude.com/docs/en/models/overview)及[Claude Code 强度说明](https://code.claude.com/docs/en/model-config#adjust-effort-level)，记录在 `research/claude-model-catalog.json`；SDK 账户可用范围与默认强度仍须按实际接入确认，空值跟随执行器，不臆造 SDK 默认档位。

Cursor 主列表按用户要求只展示 Auto、Grok 4.7 与 Composer 2.5（`composer-2.5`）。本机 CLI 目录返回 Grok 4.7 的 low/medium/high/xhigh 四档，Auto 与 Composer 2.5 无独立 effort；fast 变体不放入本次主要列表。CLI 参数语法与 ACP 源码已确认配置路径，真实会话切换和推理仍待联调。[官方模型参数](https://cursor.com/docs/sdk/typescript#model-parameters)要求从目录发现合法参数和值，不硬编码统一强度等级或自行拼接模型后缀。Cursor 主路线仍为 CLI ACP，参数选择扩展按版本验证；同进程模型变更会影响全部会话并写入 CLI 偏好，因此任务/会话使用独立 ACP 进程，并继续联调持久偏好与并发隔离。

项目导入与移除为 P0（FR-15，需求总数仍为 18）：无项目空状态、侧栏“本机项目”旁及窄屏项目栏提供导入入口。正式 SwiftUI 应用通过系统目录选择器导入已有本地 Git 仓库，校验目录、访问权限和 Git 状态；填写名称、路径和默认执行器，不自动 clone、安装或启动 AI。活动项目按规范路径去重：命中活动项目则切换；已移除的本地目录以后可重新导入为新的项目记录与空工作空间，不恢复旧 ID 或历史数据。项目拥有独立任务、聊天和运行数据，支持侧栏切换。

每个项目的“…”菜单提供“移除项目”，窄屏从当前项目菜单进入；确认框显示名称、路径及受影响的任务、会话与运行记录。移除将项目及关联应用记录移出活动工作空间，不删除本地仓库、代码、分支或 worktree；其他项目及全机执行器认证保留。旧存储可保留内部兼容，不要求永久清空，但不提供已移除项目列表或恢复功能。活跃主/子 Run、正在停止/阶段屏障或 Skill 导入中阻止移除，引导先停止或等待。同目录以后可重新导入为新项目，不承诺原 ID、任务、会话、运行日志或来源关系恢复；最后一个项目移除后进入无项目空态，刷新不自动补回 sample，仍可导入，没有已移除项目或重置演示入口。

普通聊天已移到项目层级：全局工作台不提供普通聊天导航，每个项目下展示会话列表和“新建会话”入口。可直接点选具体会话，切换项目保留独立历史与选中状态；新导入项目会话列表为空。任务主会话与项目普通会话分开保存；普通会话没有任务阶段，可按当前执行器、模型、强度和原生权限直接读取、修改项目代码或运行命令，无需先创建看板任务。其 Run 属于 Conversation，审批、停止、恢复和配置快照同样记录，写入遵守项目授权目录并与任务共享同目录唯一写入锁。代码请求或 AI 建议不自动建任务，仅用户明确要求转任务或导入时创建卡片；完全访问权限不因此默认开启。聊天页顶部只读显示项目与当前会话名称，不提供切换下拉；打开或新建会话仍使用项目侧栏。窄屏当前项目会话入口仅打开当前会话，不展开列表或提供新建、切换下拉。

已移除独立 Agent 配置页面和导航入口。执行器按需调用的内部 Agent，其状态、摘要和证据在任务主会话与已有运行记录中展示，无需用户配置固定角色列表。任务唯一活跃主运行、同目录唯一写入者、阶段停止屏障和独立验收报告等内部规则继续保留；会话执行器选择和认证弹窗仍限定为 Codex、Claude、Cursor。

执行权限与隔离为 P0（FR-18），功能需求共 18 项：输入框底栏左侧盾牌菜单采用 Codex 式三行“请求批准 / 帮我批准 / 完全访问权限”，选中项勾选；不展示沙箱、审批及审批方的多字段表单，也不增加高级入口或设置页。预设按执行器原生能力映射，不可用项禁用并说明；默认/未知和已有自定义组合仅显示短说明，不伪造预设勾选。选择后按会话/任务及执行器保存恢复，只影响下一次回复/Run，旧快照保持不变。

三种执行器的同名预设不代表相同执行边界：Claude Haiku 不提供“帮我批准”，“完全访问权限”默认禁用，须执行器允许且原生会话启动已授权；Cursor allow 规则内操作可直接执行，已有拒绝规则仍有效。三行名称不承诺逐操作询问或无条件访问全部文件。后台继续区分隔离和审批，原生映射字段仅列在 `prd.html#native-permission-contract` 技术适配契约。普通会话服从当前原生权限、项目授权目录与目录写入锁，只有看板任务额外受讨论/验收只读等阶段规则收紧；worktree 不等于 OS 沙箱，Claude Shell 沙箱也不覆盖全部工具。明确要求的隔离不可用时阻止启动，不静默降级或擅用 force。

HTML 全部权限行为为演示，未验证真实 OS 隔离、权限拒绝或强制终止；默认跟随执行器时保留未知语义，真实效果在 Adapter 联调中确认。研究依据保存在 `research/executor-sandbox-capabilities.json`，明确要求的隔离范围无法覆盖时阻止启动并报告。

执行器认证检测为 P0（FR-17）：桌面全局侧栏底部提供“执行器与认证”入口，窄屏无侧栏时使用头部齿轮，均打开原轻量认证弹窗，提供手动检查/重新检测；项目菜单移除认证项，仅保留移除等项目操作，桌面头部齿轮去重。首次使用、切换执行器及启动实际 Run 前自动只读检测。状态包括未检测、检查中、未安装、未认证/需 SDK 凭证、已认证、凭证已配置未验证、检测失败/未知；超时可重试，检测失败不等于未登录。安装和认证属于本机共享状态，项目只保存执行器选择；认证状态与模型权限、额度和实际运行能力分别验证。认证引导返回后重新检测，不自动启动任务或重放写操作，不提供全局“项目与设置”入口、独立设置页、Providers 或 Agent 配置页面；关闭弹窗返回当前工作视图。无项目时也可使用对应的全局认证入口；认证状态与项目默认执行器选择功能保持不变。窄屏项目栏提供当前项目菜单及导入入口，窄屏导航仅为看板、会话、记录。

Codex CLI/账户接口检测待联调；Cursor 本机 `status` 已返回认证状态且模型目录读取成功，未执行登录动作；必须使用经校验的绝对路径，避免本机裸命令 `agent` 命中 Grok。Claude CLI `auth status` 不证明 Agent SDK 可用：SDK 需按[官方认证要求](https://code.claude.com/docs/en/agent-sdk/quickstart)检测 API key 或支持的云认证，凭证存在不代表有效，也不能默认复用 claude.ai 订阅登录。HTML 明确模拟检查和认证指引，不执行命令、真实登录或密钥输入；凭证不进入任务、聊天和 localStorage。真实凭证及模型验证须在实现后联调。

内置任务清单导入 Skill 为 P0（FR-16）：在项目普通会话通过通用附件按钮提供 `.xlsx`、`.xls`、`.csv` 任务表，再明确发送“将附件任务导入看板”；或发送 Issue 列表、单个 Issue、一组链接并要求导入。该指令已授权创建任务，Agent 自动识别来源、工作表与字段，读取明确范围，标准化并去重后直接幂等创建所属项目的待处理任务。会话回复成功任务编号、重复跳过与错误；不增加来源选择、字段映射、候选勾选、审批或确认弹窗，也不设置专属 Skill/Agent 使用按钮或独立导入页面。仅附加文件或链接不自动导入。新任务不自动运行 AI 或推进阶段；Skill 不增加执行器候选，应用层 ImportService 可处理相同聊天请求并提供解析和提交。

Excel 与 Issue 的 HTML 示例任务和结果不代表已解析上传工作簿或已抓取远程任务。真实工作簿自动识别、私有来源连接授权、分页读取和事务行为需在实现阶段验证；CSV/TSV 已验证在浏览器本地实际解析、批量创建与去重。来源无法识别、范围歧义或缺少权限时，仅在会话请求必要澄清或连接授权，不要求聊天中的密钥。完整读取失败或事务失败创建零任务；部分行缺标题等错误时导入其余有效行，并报告错误跳过；重复自动跳过且来源可追溯。

HTML 的项目导入只模拟输入路径和项目记录，不访问本机代码库，也不执行 Git 或目录权限校验；移除只修改浏览器活动演示记录，不删除真实目录、分支或 worktree，也不终止真实进程；旧数据兼容保留不等于提供恢复功能。会话可在浏览器内读取用户主动附加的 CSV/TSV 文件；Excel 仅展示文件名并使用内置样例，不读取单元格。输入不存在的路径仍是演示数据，不能作为真实校验通过的证据；真实导入与异常状态需在 SwiftUI 实现中验证。

推荐体验路径：模拟导入项目并切换 → 在项目下新建或选择普通会话 → 附加任务表或粘贴 Issue 链接并发送导入指令 → Agent 直接导入并在会话报告结果 → 打开待处理任务 → 进入讨论 → 确认方案 → 开发 → 在主会话查看执行摘要与运行记录 → 按需进入验收 → 模拟代码变化使报告失效 → 按需重新验收 → 人工确认完成。也可从开发直接手动完成；报告缺失、未通过、过期或方案尚未确认均不阻止完成，已有报告保留作参考，运行停止与并发保护继续保留。也可直接新建任务并保存备注。项目普通会话保持独立上下文。

Cursor 调研入口：`prd.html#cursor-integration`。官方来源链接随正文列出；10-06 初始化探针保留在 `research/cursor-integration-probe.json`。10-07 CLI 模型/强度目录与 ACP 源码补充见 `research/cursor-reasoning-probe.json`，未发起模型请求；实际会话配置、推理效果、审批与停止分别联调，不将静态实现或配置接受当作模型运行证明。
